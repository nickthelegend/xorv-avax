# x402 on Avalanche Fuji (exact scheme)

Xorv's gateway speaks x402 v1 with the `exact` EVM scheme on network `avalanche-fuji`. Any client that can sign an EIP-3009 `TransferWithAuthorization` can pay it.

## 1. Ask without paying

```http
POST /v1/chat/completions
content-type: application/json

{"model":"groq:openai/gpt-oss-20b","messages":[{"role":"user","content":"hi"}],"max_tokens":1200,"xorv":{"verify":false}}
```

```http
HTTP/1.1 402 Payment Required

{
  "x402Version": 1,
  "error": "X-PAYMENT header is required",
  "accepts": [{
    "scheme": "exact",
    "network": "avalanche-fuji",
    "maxAmountRequired": "2800",
    "resource": "http://127.0.0.1:5421/v1/chat/completions",
    "description": "One sealed-bid auction for groq:openai/gpt-oss-20b: up to 1200 tokens at most 2000 micro-tUSD per 1k tokens, plus two spot-check fees. Unused escrow is refunded on-chain.",
    "mimeType": "application/json",
    "payTo": "0xd2555e5b231957f4810f78029341cf4936e89f74",
    "maxTimeoutSeconds": 300,
    "asset": "0x2210a2161b13a1a2375951577b506707867f9739",
    "extra": { "name": "Xorv Test Dollar", "version": "1", "chainId": 43113, "job": { "model": "groq:openai/gpt-oss-20b", "maxRate": "2000", "maxTokens": 1200, "alwaysCheck": false, "commitSecs": 10, "revealSecs": 10, "workSecs": 90 } }
  }]
}
```

`maxAmountRequired` is the job's escrow: the buyer's ceiling (`xorv.max_rate`, default 2000 micro-tUSD per 1k tokens, i.e. $2 per 1M) times `max_tokens`, plus two check fees. It is a ceiling: the job is charged the cleared rate times the tokens used, and the rest is refunded on-chain to the signer.

## 2. Sign and retry

Sign EIP-712 `TransferWithAuthorization(from, to = payTo, value = maxAmountRequired, validAfter, validBefore, nonce)` on the domain `{ name: "Xorv Test Dollar", version: "1", chainId: 43113, verifyingContract: asset }`, then send it base64-encoded:

```json
{ "x402Version": 1, "scheme": "exact", "network": "avalanche-fuji",
  "payload": { "signature": "0x…", "authorization": { "from": "0x…", "to": "0xd255…9f74", "value": "2800", "validAfter": "…", "validBefore": "…", "nonce": "0x…" } } }
```

```http
POST /v1/chat/completions
X-PAYMENT: eyJ4NDAyVmVyc2lvbiI6MSwic2NoZW1lIjoiZXhhY3QiLC…
```

`packages/sdk/src/x402.ts` has `signPayment`, `encodePayment`, `decodePayment` and `verifyPayment`; `scripts/x402-client.ts` and the MCP tool `xorv_ask` are complete clients.

## 3. Settlement

The gateway (the facilitator) checks network, payee, amount, expiry, signature and the payer's balance, rejects a nonce the token has already consumed (HTTP 409), and calls `X402Router.payAndPost(job, authorization)`. In that one Fuji transaction the router pulls the payment with `transferWithAuthorization` and `XorvMarket.postJobX402` opens the job with the payer as its buyer. The response carries the answer and an `X-PAYMENT-RESPONSE` header (base64 `{ success, transaction, network, payer }`); `/api/chat` returns the job id immediately instead of waiting.

Front-running: if a third party submits the signed authorization directly to the token first, the money reaches the router without a job and the gateway call fails with a clear error. `X402Router.refundStray(authorization)` then returns exactly that payment to the signer, once; the token records the digest of the authorization that consumed each nonce, so a different or posted authorization cannot be refunded.
